# B1 — A club that works the day it is created

**Track:** B (backend/web) · **Worktree:** `track-B` · **Migration slot:** `20261002100000`
**Runs in parallel with:** N1, Q1 · **Blocks:** B2

## Why this exists

`create_club` builds a course, seven departments, ten routing rules and an
owner invite, and **no locations**. No locations means no placard can be
minted, which means no member can report anything. A new club owner signs in
to an empty shell. Verified by reading the function and by querying production.

## Goal

A club created by one command can take a member report end to end, with no SQL
and no hand-holding.

## Build

**Migration `20261002100000`** — the only slot you may use.

- `create_club` gains a course template: `p_holes int default 18` plus the
  standard facilities — clubhouse, practice range, cart barn, halfway house,
  and two on-course restrooms — inserted as `locations` in play order. Holes
  first by number, then facilities alphabetically, the same order
  `getLocationsForFiling` already sorts by.
- `mint_placard_batch(p_course)` mints every active location's placard in one
  call and returns what it made. The owner prints a sheet instead of clicking
  two dozen times. Reuse `mint_placard`'s body rather than copying it — see
  rule 4.
- Restate `revoke ... from public, anon` and the intended grant after every
  `create or replace function`, the pattern every migration here follows.

**App** — a first-run checklist on `/app` for an incomplete club: add staff,
turn on alerts, set the placard address, print placards. Driven by data, so it
disappears by being completed, never by a dismiss flag.

## Refactor while you are here

`lib/queue/reports.ts` writes every read twice, once for PGlite and once for
Supabase — five forks in that file, three more in `actions-db.ts`. Do not add a
ninth. Any read you need goes behind a single adapter, and you may collapse the
neighbouring ones if it is cheap. This is on the Debt Register.
