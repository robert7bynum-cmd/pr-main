# N1 — The native shell

**Track:** N (native) · **Worktree:** `track-N` · **Migration slot:** none
**Runs in parallel with:** B1, Q1 · **Blocks:** N2

## Why this exists

Every iPhone on the roster can currently receive nothing. `push-setup.tsx`
detects iOS and shows "the ProResponse app is on the way" — an app that does
not exist. One of three staff has missed twelve pages because of it, and no
test caught it because nothing is broken. This session builds the app that
message has been promising.

## Goal

The existing web app, running as a real app on both phones, launching from a
home screen icon and loading a live queue. No interface rewrite — the whole
point is that the interface is already good and gets reused.

## Approach

Capacitor wrapping the deployed Next.js app. The only native code is app
chrome; everything inside the frame is the site that already works. Do not
start a React Native rewrite — the interface is not the problem.

Decisions already made, do not relitigate:
- Capacitor, not Expo or React Native.
- One shared shell for both platforms.
- The app points at the deployed production URL, not a bundled static export.
  The app is server-rendered and session-cookie authenticated.

## Build

- Capacitor scaffolding, iOS and Android projects, bundle identifiers.
- Icons and splash screens. Use the existing brand colors, not defaults.
- Safe areas: the queue must not sit under the notch or the home indicator.
- Android hardware back button maps to in-app navigation, not app exit.
- Status bar styling that matches the app's own ground in both themes.

## Files you own

```
capacitor.config.ts
ios/
android/
package.json      -> ONLY a "// native" block appended at the end of scripts
```

Track B owns `supabase/`, `app/`, `lib/`, `components/`. Do not touch them.
`components/staff/push-setup.tsx` belongs to N2, not this session.

## Exit criteria — demonstrate, do not assert

- [ ] `npx cap doctor` reports both platforms healthy
- [ ] The app builds and launches in the iOS simulator
- [ ] It signs in and loads a real queue from production
- [ ] Navigation works, including the Android back button
- [ ] Nothing is clipped by the notch or home indicator
- [ ] `npm run gate` passes
- [ ] A simulator screenshot is included in the report

## Notes

You have an iOS simulator available through the simulator tools — attach the
panel before building so the result is visible. Android needs Android Studio;
if it is not installed, say so rather than guessing, and finish the iOS half.

Push notifications are N2. Do not start them here, even though it is tempting
while the native projects are open. N2 depends on a shell that is known good.
